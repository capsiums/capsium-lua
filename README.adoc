== Purpose

The Capsium Nginx extension is an OpenResty/Nginx reactor that serves
Capsium packages (`.cap` files, ZIP format) directly through Nginx with
Lua. Drop a `.cap` file into the packages directory, optionally configure
a mount point, and the package is served — extracted on demand, verified,
and routed.

== Features

* *Single module tree* — one framework-agnostic core (`lib/capsium`) plus a
thin Nginx glue layer (`lua/capsium`); no duplicated logic
* *Integrity verification* — SHA-256 checksums from `security.json` are
verified at extraction; tampered packages are rejected with 5xx and reported
by `content-validity`
* *Manifest-driven routing* — routes are auto-generated from `manifest.json`
per the Capsium routing rules (dual HTML routes, index, dataset routes)
* *Canonical + legacy schemas* — metadata, manifest, routes, storage and
security files are accepted in both the canonical forms and the legacy gem
forms (normalized on read)
* *Config-driven mounts* — packages are mounted by Host/path prefix from
`config.json`; every package is also auto-mounted at
`/capsium/<package-name>`
* *Cold-start introspection* — `/api/v1/introspect/*` endpoints lazily
extract and load packages on demand
* *Per-mount headers and CORS* — custom headers and full CORS handling
(including preflight) per mount

== Architecture

.Module structure
[source]
----
lib/capsium/                  Framework-agnostic core (the rock)
├── utils.lua                 Pure helpers (tables, JSON files, paths)
├── mime.lua                  MIME type detection (text/javascript per RFC 9239)
├── csv.lua                   Minimal CSV parser (dataset support)
├── reactor.lua               Reactor core: package management + introspection
├── package/
│   ├── package.lua           Package model (OOP): load/normalize/resolve
│   ├── extractor.lua         Atomic .cap extraction (tmp dir + rename)
│   ├── router.lua            Schema normalization + route auto-generation
│   └── security.lua          security.json parsing + SHA-256 verification
└── adapters/
    ├── nginx.lua             fs/zip adapters (LuaFileSystem + lua-zip)
    └── hash.lua              SHA-256 (resty.sha256 in OpenResty,
                            pure-Lua fallback elsewhere)

lua/capsium/                  Nginx glue (only code that touches ngx)
├── init.lua                  Entry point: wires adapters into the core,
│                             request handling, introspection API
└── config.lua                config.json loading + mount resolution
----

The core never references `ngx`; the glue never implements domain logic.
Other platforms can plug in their own fs/zip/hash adapters.

.Request flow
[source]
----
HTTP Request
     │
     ▼
generic location /  ──►  capsium.handle_request()
     │                     ├─ resolve mount (Host + path prefix from config)
     │                     ├─ method check (GET/HEAD; OPTIONS w/ CORS)
     │                     ├─ reactor:get_package(name)
     │                     │    ├─ extract .cap (atomic, verify SHA-256)
     │                     │    └─ load package (metadata/manifest/routes/storage)
     │                     ├─ package:resolve(subpath)
     │                     └─ serve static file / dataset JSON
     ▼
location /api/v1/introspect ──► capsium.handle_introspection()
----

== Package schemas

Both canonical and legacy forms are accepted and normalized on read
(see the Capsium architecture decisions document):

* `metadata.json` (required) — legacy array `dependencies` are normalized
to the canonical object form
* `manifest.json` — canonical `{"resources": {path: {type, visibility}}}`;
legacy `{"content": [{file, mime}]}` or `{"content": {name: mime}}`.
When absent, the manifest is generated by scanning `content/`
* `routes.json` — canonical `{"index": ..., "routes": [{path, resource |
dataset}]}`; legacy array or object forms with `target.file`
(content-relative). When absent, routes are auto-generated:
** `index` → `content/index.html` (also routed at `/`)
** every manifest resource under `content/` routed relative to `content/`
** HTML files get dual routes: `/page` and `/page.html`
** every dataset gets `/api/v1/data/<id>`
* `storage.json` — canonical `{"storage": {"dataSets": {...}}}`;
legacy `{"datasets": [{name, source, format, schema}]}`. Dataset sources
are served as JSON (`.json` served as-is, `.csv` converted to JSON
objects). YAML and SQLite datasets are not supported by this reactor
* `security.json` — when present, every listed file's SHA-256 is verified
at extraction; the package is *rejected* on mismatch (5xx with reason).
`content-validity` reports the verification result

== Configuration

Configuration is read from `$CAPSIUM_CONFIG_PATH`, else the first existing
of `/etc/capsium/config.json`, `/etc/capsium/nginx/config.json`,
`/var/lib/capsium/config.json`, `./config.json`.

.Example `config/config.json`
[source,json]
----
{
  "package_dir": "/var/lib/capsium/packages",
  "extract_dir": "/var/lib/capsium/extracted",
  "cache_enabled": true,
  "cache_ttl": 3600,
  "log_level": "info",
  "mounts": [
    {
      "package": "mn-samples-iso-0.1.0.cap",
      "path": "/app",
      "domain": "example.com",
      "options": {
        "cache_ttl": 7200,
        "headers": {
          "X-Frame-Options": "SAMEORIGIN",
          "X-Content-Type-Options": "nosniff"
        }
      }
    },
    {
      "package": "api-1.0.0.cap",
      "path": "/api",
      "options": {
        "cors": {
          "allowed_origins": ["https://example.com"],
          "allowed_methods": ["GET"],
          "allowed_headers": ["Content-Type"],
          "max_age": 600
        }
      }
    }
  ]
}
----

Top-level keys:

`package_dir`:: Directory containing `.cap` files
(default `/var/lib/capsium/packages`)

`extract_dir`:: Extraction target (default `/var/lib/capsium/extracted`)

`cache_enabled`:: Use the `capsium_cache` shared dict to cache
introspection responses (default `true`)

`cache_ttl`:: TTL in seconds for the shared-dict cache (default `3600`)

`packages_config_dir`:: Optional directory with per-package `<name>.json`
mount configs (merged with `mounts` at startup)

Mount entries:

`package`:: Package filename (`.cap` extension optional)

`path`:: Mount path prefix (default `/capsium/<package-name>`)

`domain`:: Virtual host. Advisory: the mount answers on all hosts, and is
preferred for the named host when mounts overlap

`options.cache_ttl`:: Static `Cache-Control` max-age override for this
mount (default `31536000` → `public, max-age=31536000`)

`options.headers`:: Extra response headers applied to every response from
this mount (an explicit `Cache-Control` here wins over `cache_ttl`)

`options.cors`:: CORS policy: `allowed_origins` (array, `*` supported),
`allowed_methods`, `allowed_headers`, `expose_headers`, `max_age`.
Preflight `OPTIONS` requests are answered with `204` when CORS is
configured.

Every package in `package_dir` is always also available at
`/capsium/<package-name>` without configuration. `/api/v1/introspect`
is reserved.

Package routes are GET-only: other methods receive `405`
(`Allow: GET, HEAD`); HEAD is served like GET without a body. Dynamic
`handler` routes are accepted by the parser but answered with `501`.

== HTTP API

Package serving:: routes from the package under its mount point.

Introspection (GET only)::

`/api/v1/introspect/metadata`::: `{packages: [{name, version, author,
description}]}`

`/api/v1/introspect/routes`::: `{routes: [{package, routes: [{method,
path}]}]}`

`/api/v1/introspect/content-hashes`::: `{contentHashes: [{package,
hash}]}` — SHA-256 of the `.cap` blob

`/api/v1/introspect/content-validity`::: `{contentValidity: [{package,
valid, lastChecked, reason?}]}` — actual integrity verification result

All introspection endpoints lazily extract and load packages on demand:
a freshly started reactor reports every `.cap` in `package_dir`.

== Running with Docker

[source,bash]
----
docker build -t capsium-nginx .
docker run -d -p 8080:80 \
  -v $PWD/packages:/var/lib/capsium/packages \
  -v $PWD/config:/etc/capsium \
  capsium-nginx
----

Or with docker compose (`docker-compose up -d`).

The base image is pinned: `openresty/openresty:1.27.1.2-12-alpine-fat`
(see the `BASE_IMAGE` arg in the `Dockerfile` and the `Rakefile`).

== Testing

All Lua tooling runs in Docker; the RSpec integration suite runs on the
host against the Dockerized reactor.

Lua unit tests (busted) and lint (luacheck)::

[source,bash]
----
docker build -t capsium-nginx:test .
docker run --rm -v $PWD:/src -w /src capsium-nginx:test sh -c \
  'luarocks install busted && luarocks install luacov && busted --verbose'
docker run --rm -v $PWD:/src -w /src capsium-nginx:test sh -c \
  'luarocks install luacheck && luacheck lib lua test'
----

(or `rake lua:test` / `rake lua:lint`)

Integration suite (RSpec, needs Docker + Ruby)::

[source,bash]
----
bundle install
bundle exec rake ci     # builds fixtures + image, starts container, runs specs
----

`rake fixtures` regenerates the generated `.cap` test fixtures (canonical
package with `security.json`, tampered variant, multi-package and dormant
fixtures) via `spec/fixtures/build_fixtures.rb`. The
`mn-samples-iso-0.1.0.cap` fixture is a real legacy-format package.

Useful rake tasks: `rake docker:start|stop|restart|logs|shell`,
`rake spec`, `rake test`, `rake clean`.

== Continuous integration

* `test.yml` — busted matrix (Lua 5.1–5.4, LuaJIT 2.1) + luacheck job
* `nginx.yml` — RSpec integration suite via `rake ci`

Both run on push/PR, manually, and weekly (Mondays 06:00 UTC).
